## 3. ما تم تنفيذه

### 3.1 سكربت اختبارات السيناريوهات

**الملف الجديد:** `database/tests/PHASE_8_SHIFTS_SCENARIOS.sql`

**المبدأ التصميمي:** سكربت SQL واحد يحتوي **10 اختبارات** يُغلَّف كل واحد منها داخل `SAVEPOINT` / `ROLLBACK TO SAVEPOINT`، ويُختتم الكل بـ `ROLLBACK` خارجي. النتيجة: يمكن تشغيله مباشرة على قاعدة بيانات الإنتاج (Render) **دون أي أثر جانبي**.

#### السيناريوهات المُغطّاة:

| # | السيناريو | الهدف |
|---|---|---|
| 1 | إقفال يدوي بدون فواتير معلّقة (Happy path) | يتأكد أن `markShiftClosed` ينتج `status='closed'`, `auto_closed=false` |
| 2 | عدّاد الفواتير المعلّقة | يتحقق من منطق رفض الإقفال عند وجود `paid_at IS NULL AND cancelled_at IS NULL` |
| 3 | الإقفال التلقائي (`runAutoClosurePass`) | تاريخ ماضي يُكتشف كمنتهي الصلاحية، وتاريخ مستقبلي لا يُكتشف |
| 4 | إعادة الفتح قبل بدء الفترة التالية | يجب أن يُسمح |
| 5 | إعادة الفتح بعد بدء الفترة التالية | يجب أن يُرفض (`RuntimeException`) |
| 6 | يوم كامل صباحي (`day_mode='morning_only'`) | لا تُنشأ فترة `evening` في هذا اليوم |
| 7 | يوم كامل مسائي (`day_mode='evening_only'`) | لا تُنشأ فترة `morning` في هذا اليوم |
| 8 | عمود `visits.shift_id` و FK | بنية قاعدة البيانات صحيحة |
| 9 | قبول `AUTO_CLOSE` في `audit_logs.action` | قيد CHECK مُحدَّث بشكل صحيح |
| 10 | قيد التفرّد `uq_shifts_date_type` | لا يمكن إنشاء فترتين لنفس اليوم ونفس النوع |

#### طريقة التشغيل:

```bash
psql "$DATABASE_URL" -f database/tests/PHASE_8_SHIFTS_SCENARIOS.sql
```

#### النتيجة الفعلية على Render (تاريخ المرحلة 8):

```
--- اختبار 1:  PASS ✓ — إقفال يدوي ناجح (status=closed, auto_closed=false)
--- اختبار 2:  PASS ✓ — العدّاد يعمل (0 معلّقة لتاريخ افتراضي)
--- اختبار 3:  PASS ✓ — تاريخ 2099 لم يُعتبر منتهياً
                PASS ✓ — تاريخ 2020-01-01 اكتُشف كمنتهي الصلاحية
--- اختبار 4:  PASS ✓ — يُسمح بإعادة الفتح قبل بدء الفترة التالية (10:00 < 12:00)
--- اختبار 5:  PASS ✓ — يُرفض إعادة الفتح بعد بدء الفترة التالية (13:00 >= 12:00)
--- اختبار 6:  PASS ✓ — يوم كامل صباحي: morning موجودة، evening غير موجودة
--- اختبار 7:  PASS ✓ — يوم كامل مسائي: evening موجودة، morning غير موجودة
--- اختبار 8:  PASS ✓ — visits.shift_id موجود و FK نشط
--- اختبار 9:  PASS ✓ — قيد CHECK يحتوي AUTO_CLOSE
--- اختبار 10: PASS ✓ — قيد التفرّد رفض الإدراج المكرّر
```

**النتيجة الإجمالية:** ✅ **10/10 PASS**.

#### قرارات تصميمية في السكربت:

- **`closed_by=0`** (مستخدم النظام `__system__`) لتفادي انتهاك FK `fk_shifts_closed_by`.
- **منطق "معلّقة"** = `paid_at IS NULL AND cancelled_at IS NULL` (تطابق بنية `invoices` الفعلية — لا يوجد عمود `status`).
- **تواريخ افتراضية في 2099** لتفادي التضارب مع بيانات الإنتاج.
- **تاريخ 2020-01-01** كحالة عكسية مضمونة الانقضاء.
